# 03 - 关键业务链路

> 来源: `evidence/依赖与链路图谱.yaml#business_flows`

## Flow 1: create-shortlink

- **触发**: `POST /api/v1/shortlinks`
- **目标用户**: 内部市场同事
- **关键依赖**: api / abuse-detector(进程内)/ postgres-shortlink / redis-shortlink

### 序列

![序列图](../diagrams/create-shortlink.mmd)

1. `api` 校验 URL,调 in-process `abuse-detector`
2. `api` 写 `postgres-shortlink.url`
3. `api` 预热 `redis-shortlink` 缓存

### 失败模式

- Postgres 写失败 → 返回 5xx,前端有 retry
- Redis 不可用 → 创建仍成功,但首次重定向走 DB(R-001)

---

## Flow 2: redirect + click 记录

- **触发**: `GET /{slug}`
- **关键依赖**: api / redis-shortlink / postgres-shortlink(fallback)/ click-aggregator

### 序列

![序列图](../diagrams/redirect-click.mmd)

1. `api` 查 `redis-shortlink`,miss 时 fallback 查 `postgres-shortlink`
2. `api` 302 重定向
3. `api` 异步 XADD 点击事件到 Redis stream
4. `click-aggregator` 消费 stream,批写 `postgres-shortlink.minute_clicks`

### 失败模式

- Redis 挂 → 步骤 1 fallback 命中 DB,p99 退化(R-001)
- click-aggregator crash 在 ACK 之前 → 那一批事件丢(R-002)

---

## Flow 3: abuse 名单更新

- **触发**: `POST /api/v1/admin/abuse`
- **关键依赖**: api 全部节点 / postgres-shortlink / redis-shortlink (pubsub)

### 序列

![序列图](../diagrams/abuse-update.mmd)

1. `api` 持久化新规则到 `postgres-shortlink.abuse_patterns`
2. `api` 在 Redis pubsub 上广播 reload 事件
3. 所有 `api` 节点收到事件,reload 内存中的规则集

### 失败模式

- 某节点 pubsub 断线 → 该节点规则 stale 直到下次重启
- 规模扩到 20+ 节点时可能 reload 抖动(R-003,当前 4 节点无问题)
