# arch-frame Playbook

## 1. `cr.md` 固定结构

必须按以下顺序产出：

1. 背景与目标
2. 范围
3. 明确不做的事
4. 验收标准
5. NFR
6. 关键依赖与上下游
7. 已知未知项

## 2. HARD GATE 检测 rubric

满足任意 2 项以上，默认阻塞并提示用户补充：

- 验收标准只有形容词，没有可验证标准。
- 没写 non-goals。
- NFR 完全缺位，尤其是安全、可靠性、成本、延迟。
- 依赖系统或上下游不清。
- 数据边界不清，不知道会改哪些实体或存储。
- 权限或合规要求未说明。
- 需求中存在明显歧义句，如“支持查询”“提升性能”“兼容历史数据”但无边界。

## 3. org KB 加载矩阵

- 目录不存在：`not_configured`
- 单文件不存在：`not_loaded`
- 文件存在且 schema 通过：`loaded`
- 文件存在但 schema 失败：阻塞，提示修复

## 4. 用户追问顺序

优先追问：

1. 这次变更明确不做什么？
2. 怎么判断做成了？
3. 对性能、可靠性、安全、成本有没有硬要求？
4. 一定会碰哪些系统或数据？
5. 有哪些不能碰的边界？

## 5. 输出要求

- 所有关键信息写进 `cr.md`。
- 若用户拒绝补充，必须把空缺写入“已知未知项”。
- 若继续前进用了 override，必须回写 `state.yaml.overrides`。
