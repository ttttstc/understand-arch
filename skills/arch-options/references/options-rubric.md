# arch-options Rubric

## 1. 什么时候该跑 options

满足任意一条再跑：

- 至少有两条可行架构路径
- 数据模型变化存在不同策略
- 发布/回滚路径差异大
- 某条路径会触碰 org KB 红线，另一条不会

若只是“实现细节不同”，不必强行产 options。

## 2. 方案比较维度

每个候选方案都要比较：

- 影响面
- 模块依赖变化
- 数据模型变化
- 回滚路径
- org KB 适配度

## 3. 推荐规则

- 推荐方案必须说明为何更适合当前 CR。
- 不推荐方案必须说明主要代价。
- 不允许把“看起来更先进”当推荐理由。

## 4. 模板使用

- 先用 `options-table-template.md` 摊平候选方案差异，再写推荐结论。
- 若只有两套方案，也保留完整比较维度，不要缩成随意段落。
